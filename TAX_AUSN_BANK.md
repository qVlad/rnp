# АУСН-Доходы 8% — расчёт по методике cash-basis

Воспроизводит расчёт бухгалтера-практика (файл «Стас Разметка банка с 01.01.2026.xlsx») 1:1.

## Где смотреть

- **UI**: меню → **«АУСН-Доходы 8%»** (`/tax-report-ausn`). Видно только `director` и `head_of_sales`.
- **API**: `GET /api/tax-report/ausn?from=YYYY-MM-DD&to=YYYY-MM-DD&pay_date_source=auto|proxy|actual`
- **Сервис**: [`backend/app/services/tax_report_ausn.py`](backend/app/services/tax_report_ausn.py)

## Методика

```
База_месяц  = Bank + ВЗЗ + УПД_доставки
АУСН_месяц  = База × 8%
```

Где:
- **Bank** — фактические зачисления денег WB → расчётный счёт за месяц по `paid_dt`
- **ВЗЗ** — взаимозачёт услуг WB (комиссия + логистика + хранение + удержания + штрафы), признаются как доход в месяце оказания услуги (`period_end`). Только для «Основной» отчётов
- **УПД доставки** — отдельные УПД-документы WB за доставку выкупов (только «По выкупам» отчёты), по `period_end`

### Формулы по полям `wb_report_detail`

| Стас | Поле в `wb_report_detail` | Формула |
|---|---|---|
| `G` Продажа | `retail_amount` | `SUM('Продажа') − SUM('Возврат')` |
| `T` Итого к оплате | — (вычисляется) | `ppvz_for_pay_net + Y + other_ppvz − delivery_rub − storage_fee − deduction − penalty` |
| `Y` Тов. компенсация | `ppvz_for_pay` | `SUM` для `supplier_oper_name='Добровольная компенсация при возврате'` |
| `other_ppvz` | `ppvz_for_pay` | `SUM` для прочих `supplier_oper_name` (Корректировка эквайринга, программа лояльности, и т.д.) |
| `X` ВЗЗ | — (вычисляется) | `G − T + Y` для «Основной», `0` для «По выкупам» |
| `Z` УПД доставки | `wb_payment_order.upd_delivery_amount` | Импортируется отдельно (нет в WB API) |

### Определение типа отчёта

`report_type='По выкупам'` если `realization_id` присутствует в `wb_redeem_notification.notification_number`, иначе `'Основной'`.

### Фискально-годовое исключение

Если `Основной` отчёт с `period_end.year < paid_dt.year` (например, период `2025-12-29..12-31`, оплата `2026-01-20`) — **не включается** в Bank нового года. Уже учтён в декларации за прошлый.

## Источники данных по компонентам

| Компонент | Источник | Что нужно загрузить |
|---|---|---|
| Bank | `wb_payment_order` (импорт XLSX) | «История платежей» из ЛК WB |
| ВЗЗ | `wb_report_detail` (синк через WB API) | — (автоматически) |
| УПД доставки | `wb_payment_order.upd_delivery_amount` ИЛИ `wb_redeem_notification` (fallback) | XLSX в Стас-формате с колонкой `Z` ИЛИ Documents API синк |
| Тип отчёта | `wb_redeem_notification` (синк Documents API) | — (автоматически) |
| `retail_amount` / `ppvz` / удержания | `wb_report_detail` (WB API) | — (автоматически) |

## Загрузка данных через UI

### Вариант 1: «История платежей» (минимум)

В кабинете WB → **Финансы → История платежей → Скачать в Excel**. Загрузить через `POST /api/tax-report/payment-orders/import` (UI: страница `/tax-report-ausn` → кнопка «Импорт истории платежей»).

**Покрывает**: только `Bank`.

### Вариант 2: Стас-формат (полный)

Бухгалтерская таблица с per-realization данными. Ожидаемые колонки на листе «Отчеты+УПД» (имя листа фиксированное):

| Колонка | Заголовок | Назначение |
|---|---|---|
| A | `№ отчета` | realization_id |
| D | `Дата конца` | `period_end` |
| F | `Тип отчета` | `Основной` / `По выкупам` |
| T | `Итого к оплате` | Bank amount |
| U | `Дата оплаты` | `paid_dt` (если пусто → строка считается non-paid, амт=0) |
| Z | `УПД Доставка по выкупу` | `upd_delivery_amount` |

**Покрывает**: Bank + УПД + фискально-годовое исключение.

## Параметры endpoint'а

```
GET /api/tax-report/ausn
  ?from=2026-01-01            # начало периода (по умолчанию 6 месяцев назад)
  &to=2026-04-30              # конец периода (по умолчанию сегодня)
  &pay_date_source=auto       # auto (default) | proxy | actual
  &pay_offset_days=10         # для proxy: report_date_to + N дней
```

### `pay_date_source`

| Режим | Bank-источник | Когда использовать |
|---|---|---|
| `auto` | `actual` если в `wb_payment_order` есть paid строки за период, иначе `proxy` | Default |
| `actual` | `wb_payment_order.paid_dt` + `amount` | После импорта истории платежей |
| `proxy` | `report_date_to + pay_offset_days` (оценка) | Если ничего не импортировано |

## Что произойдёт если загрузить ТОЛЬКО «Историю платежей» (без Стас-формата)

Честный ответ: **ВЗЗ совпадёт, Bank совпадёт, но 2 компонента дадут расхождения**.

| Компонент | Что будет |
|---|---|
| Bank | ✅ Точно совпадёт — paid_dt+amount есть в обоих форматах |
| ВЗЗ | ✅ Точно совпадёт — считается из `wb_report_detail` (синк WB API), не зависит от импорта |
| **УПД доставки** | ⚠️ **Fallback на `wb_redeem_notification.total_sum_with_vat`** — это полная стоимость возвратов, **не** УПД доставки (отличается в десятки раз). Для нашего dataset: реальные ~4-5k ₽/мес против ~50-130k ₽/мес из fallback → завышение базы и налога. |
| **Фискально-годовое исключение** | ⚠️ Не сработает — нужны `period_end` + `report_type` на `wb_payment_order`, которые есть только в Стас-формате. Январь 2026 при ёлом примере получает лишние +212 405.97 ₽ (отчёт `588553261` за период `2025-12-29..12-31`, оплачен `2026-01-20`). |

### Решение для «только История платежей»

Чтобы и при этом сценарии сойтись:
1. **УПД** — синкать через WB Documents API (`/api/v1/documents/...`) более детально, парсить items на «доставка vs возвраты», сохранять в отдельную таблицу. На стороне backend — TODO.
2. **Фискально-годовое исключение** — joinить `wb_payment_order` с `wb_report_detail` по `realization_id` (можно вытащить из `payment_order_id` если WB его кодирует, либо по amount-matching). Эвристика, может ошибаться.

Без этих доработок **только «История платежей» НЕ достаточно** для копейка-в-копейку соответствия. С Стас-форматом — достаточно.
