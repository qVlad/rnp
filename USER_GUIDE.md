## Юнит-экономика с редактированием цены и скидки

**Раздел в сервисе:** меню «SKU и продажи» → **Юнит-экономика** (`/units`).

### Что это

Таблица с каждым артикулом (SKU) и полным расчётом юнит-экономики: выручка,
себестоимость (COGS), комиссия WB, логистика, хранение, маркетинг, маржа, ROI.
Все колонки сортируются и фильтруются, доступен поиск по nm_id или артикулу
поставщика.

**Главная фишка** — можно прямо в таблице (без выгрузки в Excel) ввести
«Новую цену» или «Новую скидку» и сразу увидеть какая будет **«Новая маржа»**
с цветной стрелкой ▲/▼ относительно текущей.

### Зачем использовать

- **Сценарий «А что если…»:** хочу поднять цену на 50 ₽ — какая будет маржа?
  Стоит ли увеличить скидку на 5% ради ускорения продаж?
- **До решения о смене цены в ЛК WB** — посчитать impact заранее.
- **Поиск артикулов с просевшей маржой** — фильтр по марже + сортировка по
  убыточности.

### Как настроить

1. Откройте `/units`. По умолчанию показаны все ваши SKU за последние 30 дней.
2. Поменяйте период через календарь сверху (preset «7д / 14д / 30д / 90д»
   или произвольно).
3. В колонке **«Новая цена»** или **«Новая скидка»** введите нужное значение
   прямо в ячейку — «Новая маржа» пересчитается мгновенно.
4. Колонки можно скрывать / переставлять (drag-and-drop) — настройки
   сохраняются автоматически.

### Полезно для

- **Собственник:** быстрый ответ на «надо ли поднять цены по портфелю».
- **РОП:** просмотр маржинальности по всему ассортименту, выявление SKU,
  которые тянут команду вниз.
- **Менеджер бренда:** ежедневный инструмент — посчитать новую цену перед
  изменением в ЛК WB; найти артикулы с DRR > 20% или отрицательной маржой.
- **Бухгалтер:** не использует (нет доступа — этот раздел только для
  управленческого учёта).

### Возможности

- Inline-редактор цены и скидки с моментальным пересчётом маржи (TASK-LEAD-049).
- Фильтры: бренд, диапазон маржи, размерная сетка, остатки.
- Drag-and-drop колонок + персональное скрытие колонок (сохраняется в браузере).
- Архивирование / разархивирование SKU прямо из таблицы.
- Photo-preview по hover на nm_id.
- Эмодзи-теги (🏆 / ⭐ / 📦 / 🆕 / 🚨 / 🔥) — фильтр по тегам.
- Drill-down на конкретный SKU → история цен, COGS, план vs факт.

### Связанные разделы

- **`/unit-plan`** (Плановая юнит-экономика) — полная Excel-методика
  LeymanKids, 60 колонок формулы. Для глубокого планирования.
- **`/abc-analysis`** — классификация SKU по выручке/марже A/B/C.

## Калькулятор рентабельности WB-акций

**Раздел в сервисе:** меню «SKU и продажи» → **Калькулятор акций**
(`/promo-calculator`). Полная методичка — [`PROMO_CALCULATOR.md`](PROMO_CALCULATOR.md).

### Что это

Симулятор «вступать ли в WB-акцию». Вы выбираете артикулы, указываете
параметры акции (скидка %, длительность, ожидаемый рост продаж) — сервис
показывает per-SKU как изменится маржа: будет ли акция прибыльной, и какой
минимальный рост заказов нужен чтобы выйти в ноль.

### Зачем использовать

- WB регулярно приглашает в акции со скидкой 10-30%. Без расчёта легко уйти
  в минус (особенно по SKU с тонкой маржой).
- Понять **breakeven boost** — «при каком росте продаж в 1.5× / 2× / 3× акция
  окупится». Если ваша среднестатистическая акция даёт +50% продаж, а
  breakeven = +120%, то участвовать не стоит.
- Сравнить per-SKU: акция может быть прибыльной для одних артикулов и
  убыточной для других — отказаться от части.

### Как настроить

1. Откройте `/promo-calculator`.
2. **Выберите SKU** — можно multi-select из таблицы (поиск по nm_id /
   артикулу).
3. **Параметры акции:**
   - Скидка % (обычно 10-25%).
   - Длительность акции в днях (опциональный параметр).
   - Ожидаемый рост заказов (boost), % — например +80% (типично для WB).
4. **Baseline-период:** 7 / 14 / 30 дней — за какой период берём «как было
   без акции».
5. Кнопка **«Симулировать»** → получаете таблицу: текущая маржа vs маржа в
   акции + дельта + breakeven boost.

### Как читать результат

- **Зелёный фон строки** — акция прибыльна для этого SKU.
- **Красный фон** — убыток при таком сценарии.
- **Breakeven boost** — минимальный рост продаж, при котором акция окупается.
  Если ваш типичный boost от акций ниже этого числа — не участвовать.
- Колонка **«Прибыльных SKU»** в сводке: «5 из 10» — стоит ли вообще
  входить, или часть SKU исключить.

### Полезно для

- **Собственник:** стратегическое решение «участвуем ли в акции 22% к
  большой распродаже». Видит совокупную дельту маржи по портфелю.
- **РОП:** распределяет участие между менеджерами — кому какие SKU взять в
  акцию, чьи исключить.
- **Менеджер бренда:** прямой инструмент — посчитать ROI акции до участия,
  передать РОПу список «эти SKU убыточны, исключаем».
- **Бухгалтер:** не использует (это управленческий инструмент).

### Возможности

- Multi-select артикулов.
- Sandbox/preview — расчёт без сохранения, можно перебрать 5-10 вариантов.
- Сортировка по `delta_margin desc` — сразу видны лидеры.
- Опциональный preload активных акций из WB Promo Calendar API (если
  доступен) — иначе manual-input.

## Еженедельный отчёт менеджера

**Раздел в сервисе:** меню «Отчёты» → **Еженедельный отчёт** (`/weekly-report`).

### Что это

Компактный digest за выбранную неделю — для понедельника-утра.
Включает: 10 ключевых KPI с дельтами к прошлой неделе (WoW), Top-5 SKU по
выручке, Top-5 SKU по марже, активные алерты, поле для комментария менеджера,
кнопка экспорта в PDF.

### Зачем использовать

- **Менеджер** открывает в понедельник, видит как прошла прошлая неделя по
  его бренду, добавляет комментарий «была акция, X сел в out-of-stock»,
  экспортирует PDF и отправляет РОПу.
- **РОП** просматривает прогресс по всем менеджерам за неделю.
- Не нужно собирать «недельную сводку» вручную.

### Как настроить

1. Откройте `/weekly-report`. По умолчанию открыта **последняя закрытая
   неделя** (понедельник-воскресенье).
2. Навигация: кнопки `← неделя` / `неделя →` / `⏎ к текущей`.
3. Если вы менеджер — отчёт автоматически по вашим брендам. Если РОП /
   собственник — по всему юрлицу.
4. **Комментарий за неделю** — текстовое поле под алертами. Сохраняется на
   сервере — виден всем в команде (РОП открывает ту же неделю и видит, что
   написал менеджер). Поле «автор · N мин назад» показывает, кто и когда
   редактировал. Кнопка **«Сохранить»** активна только при изменениях.
5. Кнопка **«Скачать PDF»** — генерирует файл `weekly-report-YYYY-MM-DD.pdf`.

### Как читать

- **KPI с WoW дельтой** — стрелка ▲ зелёная = выручка/маржа/orders выросли
  (хорошо), стрелка ▼ зелёная = returns/DRR/expenses снизились (тоже
  хорошо). Цветовая логика учитывает «направление улучшения» per метрика.
- **Top-5 SKU** — увидеть кто тянул вверх, кто вниз.
- **Алерты** — что требует действия (out-of-stock, DRR > 20%, аномалии).

### Полезно для

- **Собственник:** weekly health-check без открытия 10 разделов.
- **РОП:** проверка прогресса команды (TASK-LEAD-061 добавит таблицу «по
  менеджерам»).
- **Менеджер бренда:** еженедельная отчётность РОПу — 1 клик «PDF» вместо
  ручного составления Excel.
- **Бухгалтер:** не использует (это управленческий отчёт, налоги — в
  `/taxes`).

### Возможности

- Авто-выбор последней закрытой недели + быстрая навигация.
- Цветные WoW-дельты с правильной семантикой «хорошо/плохо».
- PDF-экспорт (через `html2pdf.js`, рендер прямо в браузере).
- Manager-scope (видит только свои бренды) и head/director-scope (без
  фильтра).
- **Серверный комментарий** (TASK-LEAD-062): виден всей команде, не теряется
  при смене браузера/устройства. Метка автора + времени редактирования.

### Планируется добавить

- Top-3 авто-рекомендации действий: «X закончился — нужна поставка»,
  «Y DRR > 20% — снизить ставки» (TASK-LEAD-064).
- Отправка в Telegram-чат директорам в 1 клик (HYP-002).

## Отчёт по локализации заказов

**Раздел в сервисе:** меню «SKU и продажи» → **Локализация** (`/localization`).

### Что это

Анализ соответствия «склад отгрузки ↔ регион покупателя». Локализация = %
заказов, где склад находится в том же федеральном округе РФ, что и покупатель.
Низкая локализация = дальние перевозки = дорогая логистика + долгая доставка
= ниже buyout %.

### Зачем использовать

- **Узнать «куда отгружать»:** если 60% покупателей из УрФО, а на складе
  Екатеринбург лежит 5% товара — план поставки должен сместиться в
  Екатеринбург.
- **Найти проседающие SKU** — Top-10 артикулов с худшей локализацией.
- **Снижение DRR** — близкие к покупателю поставки = ниже логистика =
  выше маржа.

### Как настроить

1. Откройте `/localization`. Период — последние 30 дней по умолчанию (можно
   изменить через календарь).
2. Главный показатель сверху: **% локализации** (Hero KPI). Хорошо: >70%,
   тревожно: <50%.
3. **Разрезы:**
   - По кластеру (7 кластеров РФ + INTL).
   - По складу WB.
   - По SKU (Top-10 худших — с минимум 5 заказами для статистической
     значимости).
4. **Heatmap** склад × кластер покупателя — сразу видно несоответствия
   (красные ячейки).

### Как читать

- **Hero «% локализации» зелёный (>70%)** — поставки распределены правильно.
- **Жёлтый (50-70%)** — есть резерв оптимизации.
- **Красный (<50%)** — критично: товар лежит не там, где нужно.
- **Heatmap:** красные ячейки = «склад A отгружал в кластер B, далёкий от
  него». Перебалансировать.
- **Top-10 worst SKU** — список артикулов где локализация < 30% при
  значимом объёме.

### Полезно для

- **Собственник:** общий health-индикатор «оптимально ли распределён склад».
- **РОП:** планирование еженедельной поставки — куда грузить чтобы поднять
  локализацию. (Планируется добавить разрез «по бренду» — TASK-LEAD-065 —
  чтобы видеть, у какого менеджера проседает.)
- **Менеджер бренда:** видит свой brand-scope. Скорее **диагностический**
  инструмент — «почему мой бренд плохо доставляется» → подсказка РОПу /
  логисту.
- **Бухгалтер:** не использует.

### Возможности

- Hero KPI + breakdown по 3 разрезам (кластер / склад / SKU).
- Heatmap-визуализация склад × кластер.
- Top-10 worst SKU с brand + предметом + объёмом заказов.
- Cancelled-заказы исключены (не искажают аналитику).
- Brand-filter для менеджера (видит только свои бренды).

### Планируется добавить

- Разрез по бренду / менеджеру (TASK-LEAD-065).
- CTA «Запланировать поставку → /redistribution» с предзаполненным складом
  и nm_id (TASK-LEAD-070).

## Калькулятор стоимости транзитных поставок

**Раздел в сервисе:** меню «SKU и продажи» → **Калькулятор поставки**
(`/transit-calculator`).

### Что это

Подсчёт стоимости поставки партии товара на конкретный склад WB:
платежи за приёмку (доставку до склада) + хранение на складе за указанный
срок. Использует актуальные WB-тарифы.

### Зачем использовать

- **Перед оформлением новой поставки** — узнать «сколько отдам WB за
  логистику и хранение». Без этого расчёта вы видите стоимость только постфактум
  в P&L.
- **Сравнить склады:** на какой выгоднее везти партию (планируется
  multi-warehouse compare — TASK-LEAD-068).
- **Прогноз стоимости при изменении WB-тарифов** (планируется WoW δ —
  TASK-LEAD-072).

### Как настроить

1. Откройте `/transit-calculator`.
2. **Выберите склад** (dropdown) — список из официальных тарифов WB.
3. **Параметры партии:**
   - Количество штук в поставке.
   - Литров на штуку — объём одной единицы (важно для расчёта
     по литрам, WB округляет вверх по `ceil`-логике).
   - Длительность хранения (дней).
4. Внизу получаете **per-unit breakdown** (база + дополнительные литры +
   хранение) + **Total ₽** на всю партию.
5. Параметры запоминаются в браузере — пришли завтра, та же партия
   пред-заполнена.

### Что НЕ входит в расчёт

Сноска под результатом честно показывает что **не** учитывается:
- Внешняя логистика (доставка вашим транспортом до пункта приёмки WB).
- Acceptance fee (плата за приёмку, если есть).
- COGS (себестоимость самого товара).
- WB-комиссия (она вычитается при продаже, не при поставке).

### Полезно для

- **Собственник:** изредка — для понимания стоимости логистики при выборе
  склада или объёме поставки.
- **РОП:** при планировании квартальных / месячных поставок — сравнить
  варианты по складам.
- **Менеджер бренда:** при оформлении новой поставки — посчитать
  ориентировочную стоимость для P&L прогноза.
- **Бухгалтер:** не использует.

### Возможности

- Актуальные тарифы (sync с WB ежедневно 08:00 МСК).
- Per-unit breakdown — видно, какая часть приходит на доставку, какая на
  хранение.
- Persist параметров в браузере.

### Планируется добавить

- Multi-warehouse compare — выбрать N складов, увидеть сравнительную
  таблицу (TASK-LEAD-068).
- SKU-aware mode — подтянуть `volume_l` из карточки товара автоматом
  (TASK-LEAD-071).
- Tariff WoW δ — показать «тариф +12% к прошлому месяцу» (TASK-LEAD-072).
