# Конкурентный анализ: РНП (наш) vs MPump «РНП — Рука на пульсе» (mpump.pro)

> Дата составления: 2026-05-18. Источники: лендинг `mpump.pro` (SPA, контент извлечён из JS-бандла `index-C6C3rJ_n.js`), приложение `app.mpump.pro` (Laravel SPA, бандл `app-L4VGYk95.js`), Telegram-каналы `@mpumpnews` (914 подписчиков) и `@TopRNP`, schema.org / OG-разметка, robots/sitemap, реестр reg.ru (`mpump.ru` выставлен на продажу — у них только `.pro`).
>
> **Confidence: medium.** Триал не покупали, реальный UX внутри `app.mpump.pro` не щупали — приложение требует WB-токен и регистрацию. Список модулей восстановлен по строкам в JS-бандле приложения (~250 ключевых строк) и маркетинговым строкам с лендинга (~250 строк). Цены — единственная видимая в лендинге = 4 990 ₽/мес, остальные тарифы скрыты за регистрацией. Глубину каждого модуля оценить по строкам сложно — описываю по тому, что видно в навигации SPA + что заявлено в маркетинге.

## 0. Главный шок-вывод первой минуты

**MPump использует ровно то же название что и наш проект — «РНП — Рука на пульсе»**, тот же tagline «Сервис аналитики для Wildberries», очень близкое позиционирование (unit-экономика, План/Факт, тепловые карты, контроль прибыли). Юрлицо: **ИП Бахтеев Шамиль Равилевич** (Казань, ул. Николая Ершова 76/1 и ул. Поперечно-Гривская 1; московский адрес — 2-я Хуторская 38А, стр. 26). Они также называют сервис **«imPulse»** и **«РНП №1»**.

**Это не клон нашего кода** (стек у них Laravel + Nunito + кастомный SPA, у нас FastAPI + Vite + Tailwind). Это **параллельный продукт, который занял ту же нишу и то же имя**. У них формальный статус «официальный партнёр Wildberries» (анонс в TG), у нас — нет.

Практические следствия:
1. **SEO-конкуренция за «РНП»/«Рука на пульсе» проиграна**: при поиске «mpump» / «РНП» / «рука на пульсе wildberries» первая выдача — они. У них также есть рейтинг 4.8 (150 отзывов) в schema.org разметке для Google.
2. **Имя как бренд занято**: если планируется идти в публичный SaaS — придётся либо менять название, либо позиционироваться явно как «РНП от sellerfriends» / «РНП от Стаса» и т.п. Их название стало нарицательным внутри ниши (это видно даже по нашему собственному `MANAGER_GUIDE.md`, где «РНП» используется как термин для сегмента отчётов).
3. **Юрлицо в Казани с заявленной «1000+ селлеров»** (маркетинг лендинга) — это уже не стартап. Сегмент 1.5-30M ₽ оборота у них активный.

## 1. Карта модулей MPump

Восстановлено из навигации `app.mpump.pro` + маркетинговых блоков лендинга + 8 видео-уроков канала `@mpumpnews`.

### 1.1 Основная навигация (раздел в приложении)

| Раздел | Что внутри (восстановлено) | Уникальность для рынка |
|---|---|---|
| **Динамика** | Дельты + Теплокарта + Аномалии по дням × метрикам. «Дельты для мгновенных инсайтов» — каждый день подсвечивается ▲▼ изменение vs предыдущий. | Высокая визуальность; не уникально (TrueStats имеет heatmap, мы — `/ads-heatmap`) |
| **Финансы** | «Финансы по категориям», «Структура расходов и прибыли по отчётам и артикулам», «Динамика изменения прибыли и расходов» | Стандартный P&L; но **отдельный модуль с категорическим разрезом** — у нас аналог есть в P&L по статьям |
| **Продвижение** | Реклама WB: «Запуск/Отключение рекламы», «Изменение ставок в рекламе», «Воронка продаж и Конверсии», «Дорогая реклама (Высокий ДРР)», «Падение эффективности рекламы», алерт «Кончился рекламный бюджет» | Действия inline (старт/стоп РК прямо из сервиса) — у нас нет, мы только read-only смотрим ad_stats |
| **Поставки** | Закупка, движение, остатки. Упоминается «Скоро закончится товар», «Товар закончился везде» | Аналог нашего `/supply` + `supplies` |
| **Документы** | Документы WB | Аналог нашего Documents API (уведомления, акты) |
| **Магазины** | Multi-cabinet workspace | **Преимущество над нами**: одна учётка → несколько WB-токенов |
| **Маркетплейсы** | Кросс-МП (только WB пока публично, в TG нет анонсов Ozon/ЯМ) | Заготовка под будущее |
| **Контент** | Карточки / описания / фото; «Изменения главного фото», «Изменение скидки на товар» | Контент-аудит (не AI-генерация, а tracking изменений) |
| **Команда** | «Управление командой (Доступы)», «Создать нового пользователя», «Имитация перехода» (auth as user) | Аналог нашего RBAC, плюс **«Имитация перехода» — admin может зайти от имени менеджера** — у нас нет |
| **Лиды / Тёплые / Холодные** | Встроенный CRM по входящим лидам (?) | **Уникально**: ни TrueStats, ни Eggheads, ни мы CRM не делаем. Возможно для агентств которые ведут селлеров на их сервисе |
| **Опросы** | Их собственная опросная механика для клиентов | Внутренний продуктовый инструмент |
| **Платежи** | Биллинг и подписки на сервис | Аналог `/billing` (у нас нет) |
| **Чат с покупателями** | Встроенный chat с WB-покупателями (отзывы, вопросы) | **Уникально**: ни TS, ни Eggheads публично не делают. WB chat API доступен — они его проинтегрировали |
| **Цены и скидки** | Управление ценообразованием и скидками | Не репрайсер уровня Mayak/Anabar, но базовое управление есть |
| **Подписки** | Управление тарифами/добавление магазина | Self-service биллинг |

## 2. Что MPump делает чего НЕТ ни у Eggheads, ни у TrueStats, ни у нас

Это самое ценное — фичи которые они придумали раньше всех в нише.

| # | Фича MPump | Почему уникально | Импакт для пользователя |
|---|---|---|---|
| 1 | **Задачник внутри сервиса** («Задачник внутри РНП», «Отказ от сторонних таскеров») | Ни у кого из конкурентов нет embedded task-tracker под маркетплейс-команду | high — менеджер видит «у тебя 3 SKU без COGS и 2 кампании с ДРР>10%» и кликает «Назначить себе» прямо там |
| 2 | **Лиды / Тёплые / Холодные организации** (встроенный CRM) | Никто не делает CRM поверх маркетплейс-аналитики | medium — для агентств / B2B-селлеров с длинным циклом продаж |
| 3 | **Чат с покупателями WB прямо в сервисе** | Eggheads / TrueStats / мы — никто не интегрировал WB chat API | high — менеджер не выходит из РНП чтобы ответить покупателю |
| 4 | **«Имитация перехода» (admin sudo-as-user)** | Для саппорта и демо. Никто не делает | low (саппорт), но **критично для self-service сегмента** |
| 5 | **Режим демонстрации экрана** (скрывает имена магазинов, артикулы, фото при шеринге) | Никто не сделал | medium — для презентаций / митингов / стримов |
| 6 | **Внутренние опросы клиентов** | Они продукт-инструмент встроили в сам сервис | low (внутренний) |
| 7 | **«Анализ по сценариям / Пресеты под задачу»** | Концепт «один клик → выбрал пресет под цель → видишь нужные метрики» — у TS есть `view presets`, у нас тоже, но MPump подаёт это как «scenario analysis» = сильный маркетинг-фрейм | medium |
| 8 | **Tags с эмодзи-палитрой** (Лидер, Звезда, Подарок, Закладка, Цвет, Сердце, ...) | TrueStats имеет «склейки», но не тэг-систему такой ширины | medium — UX-привычка пользователей быстро организовывать матрицу |

### 6.2 Что копировать (3, жёстко) — ТОЛЬКО НОВОЕ

1. **Расширенная аномалия-движок** (`services/anomaly.py` → user-configurable rules + 10-13 типов)
   - **Это новое** относительно всех 3 предыдущих анализов.
   - Migration: расширить `notification_rule` (миграция 0030) типами `margin_below`, `position_drop`, `ad_budget_zero`, `negative_review_visible`, `turnover_drop`, `conversion_drop`, `cogs_missing_critical`, ...
   - Сервис: backend job каждый час пробегает по правилам, генерирует events, push в TG-бот + sidebar dot.
   - **Импакт: high** — это превращает «сервис где смотришь цифры» в «сервис который пинает когда что-то идёт не так».
   - **Сложность: S (3-5 дней)** — инфраструктура `notification_rule` уже есть, нужно расширить список типов и добавить детекторы.

2. **Event-tracker карточки + связка «изменение → метрики до/после»**
   - **Новое**: расширить `card_change_log` (уже в Eggheads-Sprint 1 для A/B) до **общего event-stream**: photo / price / ad_bid / description / size / status.
   - Pre-requisite: некоторые события мы видим в данных (price из `wb_orders`, ad_bid из `wb_ad_stats`), некоторые надо снимать snapshot из WB Content API.
   - UI: timeline на странице карточки (`/units/{nm_id}`) с маркерами событий + before/after метрик.
   - **Импакт: high** — поверх A/B-карточек это даёт «сервис всё помнит про вашу карточку».
   - **Сложность: M (1-1.5 недели)** — нужен snapshot-job + UI timeline.

3. **Embedded задачник (мини-Trello для маркетплейс-команды)**
   - **Новое и уникальное**: ни у TS, ни у Eggheads нет.
   - Migration: `tasks(id, tenant_id, title, description, assignee_user_id, due_date, status, priority, related_nm_id, related_brand, related_anomaly_id, created_by, created_at)`.
   - API: CRUD + `auto-create from anomaly` (когда движок аномалий находит проблему — кнопка «Создать задачу»).
   - UI: новая страница `/tasks` с Kanban (todo / in-progress / done) + фильтры по assignee/brand/nm + sidebar-бейдж «у тебя N просроченных».
   - **Импакт: medium-high** — превращает analytics в operations tool.
   - **Сложность: M (1-1.5 недели)**.

### 6.3 НЕ копировать (2)

1. **CRM-блок (Лиды / Тёплые / Холодные)**
   - Это вертикаль для агентств, не для нас. У нас ICP — собственник/директор/менеджер с одним кабинетом.
   - Делать CRM поверх аналитики = размытие позиционирования и год работы.

2. **Чат с покупателями WB прямо в сервисе**
   - Тяжело поддерживать: chat API WB меняется, нужна модерация, реакция на review-bombing, support 24/7.
   - Это **inbox-сегмент** (типа Help Scout / Crisp), не аналитика.
   - Отказ обоснован: chat — это много отдельных подзадач (templates, mentions, push-to-mobile, история диалогов) — отдельный продукт.

### 6.4 Один обходной ход (не имитация)

**«Audit-готовый бух-фронт + Reconciliation Δ=0% как первый класс продукта»** — это уже сформулировано в COMPETITIVE_EGGHEADS.md §4 и COMPETITIVE_TRUESTATS.md §5. MPump-анализ его подкрепляет:

- MPump позиционируется как «реальная картина продаж» — это про **operations**.
- TrueStats про «оцифровку маржи и плана-факта» — это про **management**.
- Eggheads про «увеличение прибыли через автобиддер и ЦУП» — это про **growth**.
- Мы единственные кто строит сегмент **closing the books**: «копейка-в-копейку с ЛК WB и с расчётом бухгалтера».

**MPump-специфичный угол к этому ходу**: добавить в аудит-режим **«Источник №4 — WB Документы»**. Сейчас в TrueStats-Sprint 3 аудит сравнивает 3 источника (наш P&L, WB ЛК XLSX, бух XLSX). MPump подсказывает что **Documents API (УВ + Акты)** — это четвёртая независимая сверка. Добавить её — даёт «копейка-в-копейку по 4 источникам». **Это уникально и недостижимо никем быстро.**

## Decision Log

- **2026-05-18**: анализ mpump.pro («РНП — Рука на пульсе» от ИП Бахтеев, Татарстан + Москва).
- **Главное обнаружение**: MPump = параллельный продукт с тем же названием что у нас, ту же нишу занимают. Стек у них Laravel + кастомный SPA, не клон нашего кода. У них есть статус «официальный партнёр WB», у нас — нет.
- **Утверждены 3 sprint'а новизны** (M-1 расширенные аномалии-движок, M-2 event-tracker карточки объединённый с Eggheads-A/B, M-3 embedded задачник). Sprint M-4 — UX-сахар (tags, демо-режим, passwordless) — опционально. Sprint M-5 (multi-cabinet, write-actions реклама) — только если решим агрессивно в их сегмент.
- **НЕ копируем**: CRM (Лиды), чат с покупателями, опросы, «имитация перехода», репрайсер цен.
- **Наш моат остаётся**: налоги (АУСН/УСН + per-regime exclusion + 176-ФЗ НДС) + reconciliation Δ=0% + WB Documents API + 4-сценарный калькулятор НДС.

- **Брендинг**: нужно решение по имени — «РНП» как термин уже не наше (SEO-проиграно MPump). Варианты: «РНП audit», «РНП от sellerfriends», «РНП Lite», переход на новое имя. Это **отдельный продакт-решение, не задача из roadmap**.
- **Connectivity к 3 другим анализам**: MPump-Sprint M-2 (event-tracker) объединяется с Eggheads-Sprint 1 (A/B карточек). Остальные 2 спринта — чистая новизна. Из 14 фич сравнительной таблицы — 3 в нашей разработке через MPump, 8 уже были в других roadmap'ах, 3 явно не делаем.
