# QUICKSTART_OWNER — Первый день собственника

> Этот гайд проводит тебя от первого логина до первого осмысленного P&L.
> После этого читай [`OWNER_GUIDE.md`](OWNER_GUIDE.md) — там daily / weekly /
> monthly routine.

Среднее время прохождения — **~1 час твоего активного внимания + ~30-60 мин
ожидания первого sync'а в фоне**.

---

## Что у тебя должно быть к старту

- **Доступ к сервису** — логин/пароль + URL (даёт админ, который развернул
  сервис). На пустой БД первый зашедший становится `director` через форму
  «Первый запуск» — если ты разворачиваешь сервис сам, см. [`ADMIN_GUIDE.md`](ADMIN_GUIDE.md).
- **WB-токен (Personal API)** — на `seller.wildberries.ru` → Профиль → Доступ
  к API. Скоупы (категории прав): **Статистика, Аналитика, Продвижение,
  Документы, Контент**. Без статистики не будет orders/sales, без продвижения
  — не будет рекламы и ДРР.
- **Excel с себестоимостью (COGS)** — артикулы (`nm_id`) + цена в рублях.
  Шаблон выгружается с самого сервиса (`/settings` → раздел импортов Excel).
  Если ещё не считал себестоимость поартикульно — можно загрузить хотя бы
  средневзвешенные значения, иначе P&L врёт.

---

## Шаг 1 — Подключить WB-токен (5 минут)

**Зачем:** без токена сервис не видит твоего кабинета и ничего не считает.

**Как:**
1. Залогинься в РНП
2. Открой `/settings` (в сайдбаре «Настройки», видна только director'у)
3. Найди блок «WB-токен» → вставь Personal API → «Сохранить»
4. Сервис валидирует токен и автоматически триггерит первый sync

**Что увидеть:** статус «токен валиден». В сайдбаре внизу — точка-индикатор
sync-статуса начинает пульсировать синим (идёт первичная заливка).

---

## Шаг 2 — Подождать первый sync (~30-60 минут)

**Зачем:** WB отдаёт исторические данные за ~90 дней, плюс финальный
`reportDetail` приходит асинхронно. Нужно время на загрузку и агрегацию.

**Как:**
1. Никаких действий — sync идёт в фоне через Celery beat
2. В сайдбаре внизу — точка-индикатор. Кликни на неё → откроется drawer со
   статусом sync'а: какие сущности уже подтянуты (orders / sales / stocks /
   reportDetail / ad_stats), их возраст, активные таски и WB cooldown'ы.
3. Идёшь пить чай. На Base-токене первичная заливка ~30-60 мин, на Personal
   быстрее.

**Что увидеть:** через 30-60 мин точка-индикатор стала зелёной 🟢, в drawer'е
у основных сущностей свежий timestamp. `reportDetail` приходит позже всех —
может занять до 24 часов до первого полного цикла (расписание 04:15 MSK
ежедневно).

> Если индикатор красный 🔴 — открой drawer, посмотри какая сущность падает.
> Если жёлтый 🟡 — WB сейчас в cooldown'е, ждёшь TTL (видно в drawer'е). Это
> нормально, сервис сам восстановится.

---

## Шаг 3 — Загрузить себестоимость (COGS) (10 минут)

**Зачем:** без COGS маржа и net profit в P&L врут (показывается gross margin
без вычета себестоимости товара). Алерт `cogs_missing` будет висеть на
дашборде, пока COGS не загружен для >50% торгующих SKU.

**Как:**
1. Открой `/cost-history` («Себестоимость» в сайдбаре)
2. Сначала **выгрузи шаблон** через `/settings` → раздел Excel — там есть
   `cogs` справочник, кнопка экспорта даёт пустой шаблон со всеми твоими
   `nm_id` из WB
3. Заполни колонки: артикул (`nm_id`), цена в ₽, опционально дата `effective_from`
   (default — «с начала истории»)
4. На `/cost-history` нажми «Импорт XLSX» → загрузи файл
5. Сервис покажет отчёт: сколько строк успешно, какие `nm_id` не найдены в
   кабинете (типичные опечатки в артикулах)

**Что увидеть:** на `/` дашборде алерт `cogs_missing` исчезает. В `/pnl`
строка «COGS» теперь не нулевая, margin показывает реальные цифры.

> Себестоимость можно обновлять помесячно (новая `effective_from` дата).
> Старые продажи пересчитываются по COGS, действовавшей на дату продажи.
> Подробнее — [`OWNER_GUIDE.md`](OWNER_GUIDE.md) § 4 + [`FEATURES.md`](FEATURES.md)
> «Excel I/O».

---

## Шаг 4 — Открыть дашборд за вчера (1 минута)

**Зачем:** первый осмысленный сигнал «сервис работает и показывает мои
реальные числа».

**Как:**
1. Открой `/` (главная страница)
2. В DateRangePicker сверху выбери «Вчера» (или другой закрытый день)
3. В переключателе режима данных слева — оставь дефолтный режим (preliminary
   для последних дней, hybrid для смешанной картины)
4. Смотри hero-KPI: выручка / заказы / выкупы / маржа / ДРР / net profit

**Что увидеть:** реальные числа, бьются с тем, что ты помнишь по кабинету ±5-15%
(preliminary режим работает на orders-feed, точная сверка — в P&L final-режиме).
Если выручка = 0 — sync ещё не дошёл до сегодняшней даты или вчера действительно
не было продаж.

Если есть алерты в полосе сверху — они **реальные**, не спам:
- `cogs_missing` — должен исчезнуть после Шага 3
- `stockout_soon` — стоит проверить closeness OOS у топовых SKU
- `buyout_low`, `drr_high` — повод позвонить менеджеру

## Шаг 5 — Сверить P&L с ЛК WB (за последнюю закрытую неделю)

**Зачем:** убедиться что наша картина = WB-картина (Δ = 0 ₽). Это главный
trust-эксперимент с сервисом. Если расхождение > 1% на закрытой неделе —
что-то не так с синком, fix это первым делом.

**Как:**
1. Открой `/pnl-reconciliation` («Сверка с WB» в сайдбаре)
2. Период — **последняя закрытая неделя** (понедельник-воскресенье
   ПРЕДЫДУЩЕЙ календарной недели; текущая ещё не закрыта в WB)
3. Колонка `Δ revenue_gross%` — должна быть **0.0%** или близко к нулю

**Что увидеть:** на закрытых неделях Δ = 0 ₽ по revenue_gross. Если > 1% —
строка подсвечена жёлтым, > 3% — красным. Кликни по строке → drawer покажет
разбивку по `supplier_oper_name` (где именно разъехались числа).

> Что-то расходится на > 3%? Открой `/sync-status` drawer (точка в сайдбаре)
> — посмотри возраст `reportDetail`. Если старее 7 дней — WB ещё не закрыл
> неделю. Если свежий, но разъехались — это баг, заводи `BUG-DEV-NNN` в
> `agents/bugs-dev.md`.

## Шаг 6 — Привязать Telegram (опционально, 2 минуты)

**Зачем:** утренний дайджест прибыли и алерты в реальном времени без захода в UI.

**Как:**
1. Открой Telegram, найди бота (имя — у админа, обычно `@<твой_проект>_bot`)
2. Отправь `/start` → бот пришлёт код привязки (или попросит у админа
   `/resetowner` если бот ещё не настроен)
3. Введи код в `/settings` → «Мой Telegram-чат»
4. Опционально проверь: команды `/now` (cnapshot KPI сейчас), `/pnl` (P&L за
   период), `/alerts` (что в полосе AlertsBar)

**Что увидеть:** в 09:00 MSK каждый день — короткая сводка в личку. Алерты
типа `recon_drift` / `stockout_soon` приходят в реальном времени когда
срабатывают.

## Что НЕ нужно делать (anti-patterns)

- **НЕ редактируй `.env` руками** — это работа админа. Сервис rebuild'нется
  не так как ты ждёшь, плюс есть риск потерять `JWT_SECRET_KEY` → разлогинит
  всех пользователей.
- **НЕ запускай `redis-cli DEL wb:cooldown:*`** в попытке «ускорить sync».
  Если WB сейчас в реальном penalty — следующий запрос даст 429 и продлит
  cooldown до 6 часов. Подробнее — [`CLAUDE.md`](CLAUDE.md) § Подводные камни № 5.
- **НЕ переключай tax-режим** (АУСН ↔ УСН ±НДС) без бухгалтера и без `setting_timeline`.
  Это даёт ретроспективный пересчёт декларации — может перекосить отчётность
  за квартал.
- **НЕ удаляй платёжки** на `/tax-report/payment-orders` если они не нужны
  в налоговой базе — используй toggle «исключить из АУСН» / «исключить из УСН»
  (per-regime флаги, миграция 0028). Удаление потеряет audit-trail.
- **НЕ пересинкивай весь период вручную** через `/settings` → «Sync now» с
  большим количеством дней без понимания зачем. Beat-расписание делает это
  само, ручной trigger нужен только для конкретного фикса (например после
  замены WB-токена).
- **НЕ давай свой WB-токен** менеджерам — у них своя роль `manager`, они
  видят только свои бренды и не должны иметь доступа к токену тенанта.
