# Deploy / Release Lock — РНП

> **Назначение:** координация **всего release-flow** (bump 3 файлов версий →
> commit → push → `./scripts/remote.sh deploy`). Замок ставится **в начале**
> этого процесса (до bump'а), снимается **в конце** (после деплоя).
>
> **Кто ставит/снимает:** **только** роль Release Manager
> ([`agents/release-manager.md`](agents/release-manager.md)). Остальные роли
> (Developer / Designer / ArtDir / QA / Lead / Strategist / Analyst /
> Persona-*) после `Выполнено` своей задачи передают эстафету — сами не
> бампают версии и не запускают `./scripts/remote.sh deploy`.
>
> **Single-instance:** в любой момент только один Release Manager работает
> над релизом. Второй, увидев `🔴 Занято` — ждёт или переспрашивает у
> пользователя.
>
> Подробности — [`agents/RULES.md`](agents/RULES.md) § Правило 2.6 (механика
> замка) + § Правило 2.7 (release-manager exclusivity).

## Шаблон замка (заполняй когда стартуешь деплой)

Замени блок «Статус: 🟢 Свободно» выше на:

```
## Статус: 🔴 Занято

- **Кто:** <агент / имя пользователя>
- **С когда:** YYYY-MM-DD HH:MM MSK
- **Что катит:** <короткое описание — какая фича / коммит-hash / TASK-NNN>
- **Версия:** vX.Y.Z (см. backend/pyproject.toml)
- **Ожидаемая длительность:** ~Nмин
```

После завершения деплоя (успешного или нет) — верни «🟢 Свободно» и при желании
добавь короткую запись в журнал ниже.
