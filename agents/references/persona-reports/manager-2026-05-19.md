## Chargebacks (LEAD-005) ✅✅✅

- **Это моё ежедневное** — раньше я узнавал о штрафах через 1-2 недели когда смотрел в ЛК. Теперь — лента с фильтрами.
- **Auto-close мелочи** — сохраняет фокус.
- **Workflow с claim_text** — могу подготовить претензию пока свежая память.

### Что плохо для меня (manager-scope)

1. **Я НЕ вижу `/chargebacks` под ролью manager!** 

   Проверка: роутер `/api/chargebacks/*` имеет `dependencies=[require_module("chargebacks"), require_director_or_head]` — **manager заблокирован полностью**. Но штрафы прилетают **по моим брендам**, и **именно я** должен их оспаривать, не директор!

   - → 🔴 BUG-DEV / TASK-LEAD: RBAC должен быть **«manager видит только свои brands, director_or_head видит все»**. Сейчас всё или ничего.
   - В backend: убрать `require_director_or_head`, добавить `brands_filter` на queries (как в `services/auth.current_brands_filter`).
   - На фронте: показать manager'у пункт меню «Чарджбэки WB», без `directorOrHead` флага.

2. **Brand-фильтр на chargebacks**. Даже когда RBAC поправят — мне нужно видеть только штрафы по моим SKU.
   - → TASK-DEV: join chargebacks → wb_report_detail.nm_id → products.brand; filter through `current_brands_filter()`.

3. **Кто работал** — нет поля «assigned_to». Если 3 менеджера в компании, и chargeback по бренду X — мне нужно автоматическое назначение через `brand_assignments`.
   - → TASK-DEV: `chargebacks.assigned_user_id` через `brand_assignments` на момент `sync_chargebacks`.
