## Что нашёл

### Формула расчёта транзитной поставки

Из официальной инструкции WB:

- **Тип «Монопаллета» / «Поштучно паллетой»:**
  `стоимость = тариф_транзита × количество_паллет`
- **Тип «Короб»:**
  `стоимость = тариф_транзита × объём_поставки_л`
  Тариф зависит от **общего объёма поставки** (двухступенчатая шкала):
  - до 1 500 л — более высокий тариф (например, 8-10 ₽/л)
  - от 1 500 л — пониженный (например, 1.4-2 ₽/л)

Тарифы привязаны к **паре (хаб → конечный_склад)**. Например:
- Обухово → Казань: 10 ₽/л
- Шушары → Новосемейкино: 8.3 ₽/л
- Чашниково → Сарапул: 6.7 ₽/л

С 1 апреля 2026 тарифы транзита подняты в среднем на ~20%, по отдельным
направлениям 1.5-2×.

### Список хабов (транзитных складов)

~14 хабов: Обухово, Шушары, Екатеринбург, Казань, Краснодар, Чашниково,
Чехов 1 / Чехов 2 + ряд СЦ.

### Что в WB API

**В Tariffs API (`/api/v1/tariffs/box`) отдельных полей для транзита НЕТ.**
Это публичный endpoint, который мы синкаем в `wb_tariff_box` (миграция 0040).
Транзитные тарифы доступны только в личном кабинете WB Partners:
**Поставки и заказы → Поставки (FBW) → Транзитные направления**.

→ Программный доступ к транзитным тарифам **отсутствует** (на 2026-05).
   Селлер копирует цифры из ЛК вручную.

## Какую формулу приняли в имплементации

Поскольку в API нет транзитных тарифов и формула отличается от обычной
поставки (нет логистики per-unit + storage, а есть **тариф_за_литр × объём_партии**
с порогом 1500 л), используем гибридную модель:

1. **Поля input'а (manual):**
   - `transit_rate_small` — тариф ₽/л до 1500 л (default 8.0)
   - `transit_rate_large` — тариф ₽/л от 1500 л (default 2.0)
   - `volume_threshold_l` — порог переключения тарифа (default 1500)
   - + общие поля: units, liters_per_unit, конечный_склад (для compare с обычной).

2. **Формула расчёта (Frontend-only):**
   - `total_volume = units × liters_per_unit`
   - `rate = total_volume < threshold ? rate_small : rate_large`
   - `transit_cost = total_volume × rate`
   - Хранение на конечном складе (после транзита) считаем по обычному тарифу
     `wb_tariff_box` для конечного склада — это уже не часть транзита, но
     включаем для полноты «сколько стоит партия после транзита и за N дней
     хранения».

3. **Compare с обычной поставкой** на тот же конечный склад:
   - `Δ = (transit + storage) − (обычная_acceptance + storage)`
   - Положительная Δ = транзит дороже прямой поставки (но может быть быстрее
     или единственный способ).

## Что НЕ нашёл

- Программный API для получения транзитных тарифов (хаб → склад). WB не
  публикует.
- Точные коэффициенты «multiplier» транзита vs прямой поставки (формулы
  разные по структуре, не мультипликативные).
- Список всех актуальных пар (хаб → склад) с тарифами на 2026-05 в
  машинно-читаемом виде.
