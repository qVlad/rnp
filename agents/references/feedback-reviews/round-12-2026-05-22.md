**Distribution по приоритету:**
- P1 (этот спринт): 6 TASK
- P2 (следующий спринт): 7 TASK + 3 BUG (P2)
- P3 (долгий backlog): 4 TASK + 2 BUG (P3) + 3 HYP

**Главные инсайты:**

1. **TASK-LEAD-054 reporting_mode toggle** — backend ортогональность чистая, но UX
   подача сырая. Manager его боится (видит как выручка пропадает), РОП не понимает
   что значит «Управленческий» vs «Финансовый». Plain-language naming + scope
   visibility (TASK-LEAD-058/059/060) исправляет 80% боли без backend-правок.

2. **TASK-LEAD-051 WeeklyReport** — позиционирована как manager-digest, но
   используется и РОП'ом. Нужен dual-mode: manager видит свой scope, РОП —
   scoreboard сверху. Серверный комментарий критичен (без него — мина для
   manager↔РОП коммуникации).

3. **TASK-LEAD-052 Localization** — концепция работает, не хватает
   actionability (нет CTA «как починить»). Это паттерн, который повторится:
   diagnostics-only страницы → нужны actionable выходы в operational flows
   (`/redistribution`, `/supplies`).

4. **TASK-LEAD-043 ReconciliationHeroWidget** — лучшая фича пакета по explainer
   wizard'у, но 3-click navigation до объяснения недели + dev-термины
   (sync_report_detail, supplier_oper_name) в wizard'е делают её
   программистской. Deep-link + plain language → готова для seller'а.

5. **TASK-LEAD-055 KPI Breakdown** — 3 бага (BUG-DEV-010/012/013), один из
   которых (BUG-DEV-013 commission sign) может давать рассинхрон Σ breakdown
   ≠ Dashboard KPI. Финансовая фича без тестов — рискованно, фикс с тестами
   обязателен.

6. **TASK-LEAD-053 TransitCalculator** — узкий nice-to-have, использование
   раз в месяц при поставке. Multi-warehouse compare (TASK-LEAD-068)
   превратил бы его из «калькулятора» в «инструмент выбора склада».
