# Инструкция: как снять HAR для LEAD-016 (POST shifts.create)

**Кому:** собственник (vipryn@gmail.com) — нужен HAR из твоего личного кабинета WB.  
**Зачем:** последний блокер для запуска модуля «Перераспределение остатков». Без HAR-снэпшота **POST shifts.create** (главный endpoint для бронирования слотов) реализовать нельзя — путь и формат тела запроса не задокументированы WB.  
**Время:** 10-20 минут.

---

## 0. Предусловие

Опция «Перераспределение остатков» должна быть **подключена** в LK WB:
- ВБ Партнёры → Конструктор тарифов → опция «Перераспределение остатков»
- Стоимость: +0.5% комиссии от ВСЕХ продаж, **минимум 90 дней**
- Если опция уже включена — переходи к §1
- Если нет — **сначала прими решение** (см. STRATEGY_COCKPIT §3). Без опции раздел «Перераспределить остатки» в LK не появится.

---

## 1. Что снимаем (3 HAR-файла)

| Файл | Когда | Чего ловим |
|---|---|---|
| **A. har-create-shift.har** | В любое время дня | POST создания заявки на перемещение |
| **B. har-window-open.har** | **Ровно в 09:00 МСК** или **18:00 МСК** | Переход `quota: 0 → quota: N` |
| **C. har-shifts-report.har** | В любое время | Endpoints отчёта о перемещениях (для followup) |

---

## 2. Подготовка браузера

1. **Chrome** (Firefox тоже работает, но HAR-формат немного отличается). Версия 120+.
2. Откройте `https://seller.wildberries.ru` → залогиньтесь (SMS-логин).
3. Перейдите в раздел: **Аналитика → Отчёт по остаткам на складе → «Перераспределить остатки»**.
   - Если этот пункт меню отсутствует — опция «Перераспределение» не подключена в Конструкторе тарифов.
4. Откройте DevTools (`Cmd+Opt+I` на Mac, `F12` на Windows) → вкладка **Network**.
5. Фильтр: убедитесь что включены `Fetch/XHR`, `WS` (на всякий случай) и **`Preserve log`** включён (галочка наверху Network).
6. Очистите сетевую панель кнопкой 🚫 (clear).

---

## 3. HAR A — POST shifts.create (главный)

**Цель:** записать POST-запрос в момент клика «Создать перемещение».

1. В разделе «Перераспределить остатки»: введи **тестовый артикул** (любой свой SKU, лучше всего тот где у тебя есть остатки на 2+ складах).
2. Выбери:
   - Склад **Откуда** (где есть остатки)
   - Склад **Куда** (любой доступный приёмник)
   - Размер / характеристика (chrt)
   - Количество **5 штук** (минимум по правилам WB)
3. **Очисти Network** перед самым кликом (🚫).
4. Нажми кнопку **«Создать перемещение»** (или как она называется в твоей версии).
5. **НЕ закрывай DevTools.** Подожди 3-5 сек после клика.
6. Правый клик в Network → **«Save all as HAR with content»** → сохрани как `har-create-shift.har`.

**⚠ Важно:**
- Если ты не уверен что в окне есть quota (не 09:00 или 18:00) — WB может вернуть «лимит исчерпан» или «окно закрыто». Это **тоже полезный HAR** — мы увидим POST-payload и формат ошибки.
- Если запрос ушёл успешно — WB сделает реальное перемещение 5 единиц. Это **обратимо** (можно отменить заявку в разделе «Отчёт о перемещениях»), но всё-таки.

---

## 4. HAR B — окно бронирования (09:00 / 18:00 МСК)

**Цель:** записать переход `quota: 0 → quota: N` при открытии окна.

1. **За 1 минуту до 09:00 (или 18:00) МСК** — открой раздел «Перераспределить остатки» и зайди на любой популярный склад: **Электросталь, Краснодар-Тихорецкая, Котовск**. Эти склады закрываются быстрее всего.
2. Открой DevTools → Network → очисти.
3. **В 08:59:30 (или 17:59:30)** запускай переключение между разными складами или нажимай «Обновить» на этой странице каждые 5 сек. Это нужно чтобы поймать запросы `/quota`.
4. **Точно в 09:00:00 МСК** quota переключится с 0 на положительное число. Через 4-60 секунд снова на 0 (всё разобрали).
5. Подожди ещё 30 сек после 09:00 — пусть quota успеет вернуться на 0.
6. Сохрани HAR как `har-window-open.har`.

**Что мы ищем в этом HAR:**
- Точное время когда quota=0 → quota=N
- Тайминги между запросами /quota
- Возможно дополнительный header или cookie которые WB добавляет в окне
- Есть ли запросы `type=dst` (не только `src`)

---

## 5. HAR C — «Отчёт о перемещениях»

**Цель:** записать endpoints для следящего пайплайна — мы должны видеть статусы наших заявок (в пути / прибыло / отменено).

1. Перейди в раздел **«Отчёт о перемещениях»** (или «История перемещений», в LK переименовывают периодически).
2. Очисти Network.
3. Применяй разные фильтры: статус, период, склад. Каждое действие = новый XHR.
4. Открой 1-2 строки на детали (если есть).
5. Если есть кнопка «Отменить заявку» (для активных) — **НЕ нажимай**, просто посмотри её PUT/DELETE если хочешь её записать.
6. Сохрани HAR как `har-shifts-report.har`.

```
git check-ignore tmp/redistribution_har/  # должно вернуть путь = ignored
```

## 7. Что я (Claude) с этим сделаю

После получения трёх HAR:

1. **Анализ A** — извлеку из HAR:
   - Точный URL POST endpoint (вероятно `/ns/shifts/.../shifts/create` или `/shifts/new`)
   - Структуру JSON-body (chrt_id, from_office_id, to_office_id, qty, …)
   - Headers (возможно есть `X-CSRF-Token` или дополнительный JWT)
   - Возможные коды ответов (200 OK, 400 «нет места», 401, 429)
2. **Анализ B** — извлеку:
   - Точное время переключения quota (для калибровки NTP-sync)
   - Поведение endpoint'а в окне (rate-limit, какие codes возвращает после исчерпания)
   - `type=dst` endpoint поведение
3. **Анализ C** — извлеку:
   - GET /shifts/list или /shifts/history endpoint
   - Структуру статуса (in_transit, arrived, cancelled)
   - URL отмены (для будущего «откатить заявку»)

4. **Реализация** (~1-2 недели):
   - `WbLkClient.create_shift(chrt_id, from_office_id, to_office_id, qty)` — boilerplate уже готов в `integrations/wb_lk/client.py`
   - `WbLkClient.list_shifts()` для followup
   - `execute_window` Celery task с миллисекундной точностью (NTP-sync через chrony на проде)
   - End-to-end тест: одна реальная заявка на 5 штук в тестовом окне

5. **После реализации** — `redistribution.task.completed` event-bus publisher + Telegram-уведомление селлеру «✓ забронировано / ✗ не пойман слот».

## 9. Если опция «Перераспределение» НЕ подключена

Альтернативный путь — найти другого селлера у кого подключено и попросить снять HAR (с тестовой заявкой на 5 ед.). Например, через Telegram-сообщества WB-селлеров.

Без HAR Product #1 (Перераспределение) застрянет на этапе «рекомендации показываем, но отправить не можем». В этом виде сервис **полу-готов** — селлер увидит ROI-дашборд, но реальное бронирование останется ручным.

## 10. FAQ

**Q: HAR не содержит payload (тело запроса)?**
A: Включи `Preserve log` и убедись что в DevTools → Settings → Preferences → Network → «Record network log» включено. Иногда Chrome обрезает body для больших запросов — для нас это не проблема (POST shifts.create маленький JSON).

**Q: WB вернул капчу?**
A: Это редко но бывает. Пройди капчу, перезагрузи страницу, повтори клик. В HAR будет видна капча-route — нам этого делать **не нужно**, парсер только POST shifts.

**Q: Хочу проверить что собрал правильно?**
A: Откройте HAR в текстовом редакторе. Должны увидеть JSON с массивом `entries`. Ищите `"url"` содержащий `shifts` — должно быть несколько таких записей.
