# STRAT-003: Decision — Chrome-extension «РНП Connect» vs альтернативы

**Дата:** 2026-05-19  
**Author:** Strategist Agent  
**Контекст:** BUG-DES-004 — текущий онбординг redistribution требует от селлера копировать JWT-токен `AuthorizeV3` из Chrome DevTools. Это блокер для **non-tech** пользователей (≈80% сегмента ICP).

---

## TL;DR — Рекомендация

**Вариант B (улучшенная инструкция + видео) — на старте, в неделе.** Вариант A (Chrome-ext) — после первых 10 клиентов в managed-hosting, если данные показывают что онбординг = bottleneck. Вариант C (RuCaptcha SMS-auto) — НЕ делать; ROI отрицательный.

---

## Контекст

Сейчас в `pages/Redistribution.tsx` юзер видит модалку «Подключить LK» с инструкцией:

> «Откройте `seller.wildberries.ru`, залогиньтесь, в DevTools → Network найдите любой запрос к `seller-weekly-report.wildberries.ru` → скопируйте заголовок `AuthorizeV3` и вставьте сюда.»

**Проблема:**
- Селлер с уровнем «Selvel 0» (Excel это сложно) не знает что такое DevTools
- Селлер с уровнем «Selvel 1» (Excel-юзер) знает про F12, но не понимает что такое JWT в headers
- **Только Selvel 2+** делает это самостоятельно — это ~15-20% сегмента
- ROI редистрибуции **высок** (есть смысл подключать только когда юзер уже видит +180k₽/мес списания), но онбординг = воронка
- Если из 10 потенциальных пользователей **2** проходят онбординг → конверсия 20% → нужен AB-test с другим UX

---

## Варианты

### Вариант A — Chrome-extension «РНП Connect»

**Что:** MV3 расширение для Chrome, которое:
1. Содержит content-script на `seller.wildberries.ru/*`
2. Перехватывает любой XHR-запрос содержащий заголовки `AuthorizeV3` + `Wb-Seller-Lk`
3. Отправляет их в наш API `POST /api/redistribution/lk/connect` через background.js (с нашим cookie auth для отправки)
4. Юзер видит уведомление «✅ LK подключён к РНП»

**Pros:**
- **One-click** — юзер заходит в seller.wildberries.ru, нажимает иконку расширения, готово
- Можно потом расширить (overlay уведомлений, deep-links на наши страницы)
- 100k бесплатных юзеров Evirma подтверждают что Chrome-ext — рабочая стратегия лидгена

**Cons:**
- **Chrome Web Store ревью**: 1-7 дней при первой публикации, можно отказать
- **Поддержка**: WB меняет фронт seller.wildberries.ru → расширение ломается (видно по Evirma в отзывах)
- **Только Chrome/Edge** (Firefox MV3 differ, Safari НЕТ Web Stores для подобного)
- **Стоимость dev**: ~3-5 дней (manifest + content-script + background + интеграция с нашим API + Web Store publish)
- **Repo overhead**: новый отдельный проект (extension is separate from main app), отдельный билд, отдельный CI

**Эффективность для онбординга:** ВЫСОКАЯ — снимает основной блокер для не-технических

**Стоимость общая:** ~40 dev-часов + 4-8 часов в месяц на поддержку (обновления при изменениях WB).

### Вариант B — Видео + полированная инструкция

**Что:**
- 1-минутное видео-демо «как подключить LK к РНП за 30 секунд» — снять Loom / OBS, embed на странице
- В UI: пошаговая инструкция с **screenshots** где-стрелки-показывают-куда-нажать
- Альтернативный путь: «Не получается? Напиши нам в TG @support, мы подключим за тебя» (concierge онбординг)

**Pros:**
- **1 день работы** (запись видео + 3-4 скриншота + текст)
- **Не требует поддержки** при изменениях WB (только если UI сильно поменяется)
- Покрывает selvel 1+ (~70% сегмента) если screenshots показывают пальцем
- Можно использовать как **fallback** для других подключений (WB-токен, COGS XLSX и т.д.)
- На старте (managed-hosting, 5-10 клиентов) **concierge онбординг** работает быстрее любого автоматизированного решения

**Cons:**
- Не help'ает selvel 0 (всё равно нужен человек)
- Видео нужно перезаписать при изменении UI РНП (~раз в полгода)
- **Конверсия онбординга** не достигнет «one-click» уровня

**Эффективность для онбординга:** СРЕДНЯЯ — поднимает с ~20% до ~50-60%

**Стоимость общая:** ~8 dev-часов + 2-4 часа на видео + ~2 часа в полгода на обновления.

### Вариант C — RuCaptcha + полная SMS-automation

**Что:**
1. Юзер вводит номер телефона в нашем UI
2. Наш backend делает запрос `POST /passport/auth/login/v2` на seller.wildberries.ru
3. WB присылает капчу — мы передаём её в RuCaptcha API (~0.3 руб за решение), получаем ответ
4. Передаём решённую капчу обратно в WB → получаем SMS-prompt
5. Юзер вводит SMS-код у нас в UI → мы дергаем `POST /passport/auth/sms-verify`
6. Сохраняем `AuthorizeV3` и `Wb-Seller-Lk` без участия юзера

**Pros:**
- **Полная автоматизация** — юзер даже не знает что такое DevTools
- Универсально работает на любой ОС / браузере / клиенте
- Можно использовать для **мульти-кабинет** сценария (когда у юзера несколько ИП)
- При желании можно сохранить cookies/токены прозрачно для юзера

**Cons:**
- **3-5 недель dev** — реально сложная интеграция, недокументированный API WB-passport
- **Ежемесячная стоимость**: ~50-200 руб/месяц на RuCaptcha на одного активного юзера (зависит от частоты relogin)
- **Юридические риски**: WB-ToS пункт 9.9.6 явно запрещает программный доступ. SMS-automation = ENS-territory. С Chrome-ext WB видит «обычный пользовательский браузер»; с SMS-auto видит «нестандартный SMS-flow с одного IP».
- **WB может закрыть** flow в любой момент (как поступил с автобронью поставок 11.09.2024)
- **Reverse engineering captcha** — Yandex / Google могут добавить reCAPTCHA v3 которая просто не решается через RuCaptcha
- **Single-point-of-failure**: если RuCaptcha API падает или WB меняет captcha-провайдера → весь онбординг ломается

**Эффективность для онбординга:** ОЧЕНЬ ВЫСОКАЯ — для всех selvel-ов

**Стоимость общая:** ~120 dev-часов + RuCaptcha ~$10-20 в месяц + риск полного breakage.

## ROI анализ

**Допущения:**
- Сейчас конверсия подключения LK = **20%** (только selvel 2+)
- Целевая воронка для редистрибуции: 10 потенциальных клиентов в месяц
- Selller с подключённой LK приносит **15k₽/мес** subscription (плюс ROI от модуля)

**Вариант B (видео+инструкция):** +30 п.п. конверсии → 5 клиентов вместо 2 → **+45k₽/мес LTV-uplift**. Окупается за 1 неделю.

**Вариант A (Chrome-ext):** +70 п.п. конверсии → 9 клиентов вместо 2 → **+105k₽/мес LTV-uplift**. Окупается за 4 недели + поддержка ~4k₽/мес.

**Вариант C (SMS-auto):** +75 п.п. конверсии (≈как A) → **+112k₽/мес LTV-uplift**. Окупается за **12 недель** + риски в любой момент обнулить инвестицию.

## Рекомендация

### Сейчас (неделя 1)
**Делаем Вариант B**: видео-демо + улучшенная инструкция + concierge fallback через TG.
- Покрывает 50-60% юзеров
- Окупается за неделю
- НЕ создаёт зависимость от внешних сервисов

### Через 5-10 платных клиентов (этап SaaS-pivot)
**Оцениваем метрики онбординга** через TanStack + posthog / amplitude:
- Если конверсия LK-connect > 60% → достаточно Варианта B, не инвестируем
- Если конверсия < 40% при наплыве не-технических юзеров → стартуем Вариант A

### НЕ делаем Вариант C
- Юридические риски + WB-side instability + операционные расходы перевешивают +15% конверсии vs Вариант A
- Лучше потратить эти 120 dev-часов на новые product-фичи
